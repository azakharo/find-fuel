# FindFuel

Мониторинг наличия бензина на АЗС через API СберАЗС (sberazs.ru) с email-уведомлениями о появлении/пропаже топлива.

## Возможности

- Опрос АЗС по расписанию (cron, по умолчанию каждые 5 минут)
- Определение наличия бензина по двум критериям: `availabilityStatus == "available"` **И** `operationsCount >= 4`
- Уведомления на email через Gmail SMTP (app password) при появлении/пропаже бензина
- Учёт чётных/нечётных дней (по типу госномера)
- Хранение состояния в памяти (in-memory) — минимум зависимостей, простая Docker-сборка
- Конфигурация списка АЗС и марок бензина через env vars
- Стартовое письмо для проверки связи email-канала при запуске (не отправляется, если при старте уже обнаружен бензин)

## Установка


## Запуск локально

1. Скопируйте `.env.example` в `.env` и заполните значения:

```bash
cp .env.example .env
```

2. Запуск в dev-режиме:

```bash
npm run dev
```

3. Сборка и запуск production:

```bash
npm run build
npm start
```

## Переменные окружения

| Переменная           | Описание                                        | По умолчанию     |
| -------------------- | ----------------------------------------------- | ---------------- |
| `STATIONS`           | JSON-массив тайлов АЗС для мониторинга          | — (обязательно)  |
| `FUEL_TYPES`         | JSON-массив марок бензина (например `["ai95"]`) | — (обязательно)  |
| `PLATE_TYPE`         | Тип госномера: `odd` или `even`                 | — (обязательно)  |
| `POLL_CRON`          | Cron-расписание опроса                          | `*/5 * * * *`    |
| `SMTP_HOST`          | SMTP-сервер                                     | `smtp.gmail.com` |
| `SMTP_PORT`          | SMTP-порт                                       | `465`            |
| `SMTP_USER`          | Gmail-адрес отправителя                         | — (обязательно)  |
| `SMTP_PASS`          | App password Gmail                              | — (обязательно)  |
| `NOTIFICATION_EMAIL` | Email получателя уведомлений                    | — (обязательно)  |
| `TZ`                 | Часовой пояс                                    | `Europe/Moscow`  |

### Пример STATIONS

Тайлы для двух АЗС (Лукойл №52055 и Газпромнефть в Цыгановке):

```
STATIONS=[{"z":13,"x":5081,"y":2593},{"z":13,"x":5080,"y":2593}]
```

## Логика определения наличия бензина

Бензин марки `<target>` считается **доступным** при одновременном выполнении:

1. `fuels[type=<target>].availabilityStatus == "available"`
2. `operationsCount >= 4` (если поле отсутствует — считается равным 0)

## Логика чётных/нечётных дней

- День определяется по числу месяца в часовом поясе `TZ`.
- При `PLATE_TYPE=odd` опрос работает только в нечётные дни, при `even` — в чётные.
- В "не свои" дни API не опрашивается, уведомления не отправляются.

## Структура проекта


## Архитектурные решения

| Решение     | Выбор                         | Обоснование                                  |
| ----------- | ----------------------------- | -------------------------------------------- |
| Стек        | Node.js + TypeScript (ESM)    | Простой backend-скрипт, минимум зависимостей |
| Расписание  | `node-cron`                   | Надёжный cron для Node.js                    |
| HTTP клиент | Built-in `fetch` (Node 18+)   | Без лишних зависимостей                      |
| Email       | `nodemailer` через Gmail SMTP | Стандарт, поддержка app passwords            |
| БД          | In-memory (`Map`)             | Минимум зависимостей, простая Docker-сборка; состояние сбрасывается при рестарте (приемлемо по семантике уведомлений) |
| Дата/время  | `date-fns`                    | По правилам проекта                          |
| Тесты       | `vitest`                      | Быстрый, совместим с TS                      |
| Запуск TS   | `tsx`                         | Быстрый, без компиляции для dev              |
