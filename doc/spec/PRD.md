# Система определения появления бензина на АЗС

## Описание проблемы

Я живу в России. Сейчас осень 2026 года. В России наблюдаются проблемы с бензином:

- Бензин либо отсутствует на АЗС, либо нужно долго стоять в очереди.
- Заправится можно только в определённые дни. Если государственный номер начинается на нечетную цифру, то заправиться можно в нечетные дни. Соответственно, если номер начинается на четную, то в чётные дни. У меня государственный номер начинается на нечетную цифру (в приложении это должно конфигурироваться через environment variable).
- Заранее неизвестно, когда и на какой АЗС появится бензин. Также не известно, какой бензин появится (92-ой, 95-ый или дизельное топливо). Мне нужен бензин АИ-95.

## Постановка задачи

Мне нужно оперативно определять появление бензина на определённых АЗС. Это позволит быстро выдвинуться в сторону данных АЗС и заправить машину, проведя в очередь минимальное время.
Мне нужна система (приложение), которое будет мониторить наличие бензина на определённых АЗС и присылать мне сообщения о его появлении и пропаже (например, бензин закончился, люди перестали его покупать).
Вначале я думал о использовании телеграм бота, в который могли бы приходить сообщения о появлении бензина. Но в России Телеграм сейчас не работает без использования VPN. Поэтому пользоваться им неудобно.
Нотификации о наличии бензина отправляются в виде **email** на указанный адрес (указывается в env file). Для отправки используется личная почта Google (Gmail SMTP с app password). Выбор email обусловлен тем, что Telegram в России не работает без VPN, а SMS-провайдеры требуют платной подписки.

## Принятые решения

| Решение                            | Выбор                                                                                 | Обоснование                                                                                                                                     |
| ---------------------------------- | ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Канал уведомлений                  | Email через Gmail SMTP (app password)                                                 | Бесплатно, надёжно, без внешних провайдеров                                                                                                     |
| Логика определения наличия бензина | `fuels[type=<target>].availabilityStatus == "available"` **И** `operationsCount >= 4` | Объединение двух индикаторов через логическое И для максимальной достоверности. Если `operationsCount` отсутствует в ответе, считается равным 0 |
| Формат списка АЗС                  | JSON-массив tile-координат (без station ID)                                           | Прямое отображение на API SberAZS. Мониторятся все станции в указанных тайлах                                                                   |
| Хранение состояния                 | в памяти (файл `state/memory-store.ts`)                                               | не переживает рестарт, без внешних зависимостей                                                                                                 |
| Технологический стек               | Node.js + TypeScript                                                                  | Простой backend-скрипт, минимум зависимостей                                                                                                    |
| Заголовок `x-sberfuel-session`     | Не используется                                                                       | Проверено: API отвечает 200 OK и без этого заголовка                                                                                            |

## Предлагаемый способ решения

Существуют приложения, которые предоставляют информацию о наличии бензина на АЗС.
Например, [СберАЗС](https://sberazs.ru/).
У этого сервиса есть API.

В ответе наибольшую важность имеют следующие поля:

- Массив stations[0].fuels. Запись с type="ai95" - если поле availabilityStatus="available", то бензин скорее всего есть на АЗС.
- Массив stations[0].operationsCount - количество человек, недавно купивших бензин на данной АЗС. Для данного запроса это поле сейчас отсутствует (смотри следующий пример запроса). Если operationsCount >= 4, то с высокой степенью вероятности можно утверждать, что бензин есть на АЗС.

**Логика определения наличия бензина** (принятое решение):

Бензин марки `<target>` (например, `ai95`) считается **доступным** на АЗС при одновременном выполнении двух условий:

1. `fuels[type=<target>].availabilityStatus == "available"`
2. `operationsCount >= 4` (если поле `operationsCount` отсутствует в ответе, считается равным 0)

Оба условия объединяются через **логическое И**. Это снижает частоту ложных срабатываний, но обеспечивает максимальную достоверность уведомлений.

## Функциональные требования

Мне нужен некоторый бекенд скрипт, который:

- по расписанию (раз в 5 минут) запрашивает наличие бензина на указанных выше АЗС
- Если бензин появился (до этого его не было), то скрипт формирует уведомление: `На АЗС <название> появился бензин! Время: <дата время>`. Скрипт отправляет email на адрес, заданный через environment variable (`NOTIFICATION_EMAIL`). Для отправки используется Gmail SMTP (app password, `SMTP_USER` / `SMTP_PASS`).
- Если бензин на АЗС закончился (до этого он был), то скрипт формирует уведомление: `На АЗС <название> закончился бензин! Время: <дата время>`. Скрипт посылает сообщение. Далее, если бензина на заправки нет, не нужно посылать повторные сообщения о том, что бензин закончился.
- Сейчас меня интересуют только 2 АЗС, но в дальнейшем список АЗС может расшириться. Лучше заранее к этому подготовиться (задавать список АЗС через env var).
- Сейчас меня интересует только бензин АИ-95, но в дальнейшем меня может заинтересовать ещё АИ-92. Лучше заранее к этому подготовиться (задавать список марок бензина через env var).

## Технические ограничения

- Проект должен быть контейнеризован (Docker / docker-compose), потому что в дальнейшем я буду разворачивать его на отдельном VPS.
- Cейчас деплой делать не нужно, только подготовь все к нему (Dockerfile, docker-compose.yml, .env.example с переменными окружения).
- Код должен быть организован так, чтобы приложение можно было поднять одной командой на чистом сервере
- В конце напиши README.md с описанием проекта и инструкцией по запуску (локально из командной строки и через docker-compose),
- Покрой тестами хотя бы определение факта появления/пропажи бензина и формирование уведомления;
- Если по ходу работы принимаешь архитектурные решения (выбор хранилища для данных, библиотеки для работы с API, структура проекта), то кратко объясни, почему.
